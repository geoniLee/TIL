# TIL - 2026.11.12

## 오늘 진행한 내용

CreatePotion의 패키징 오류를 조사하고, 인벤토리 아이템 반환·획득 정책과 클릭 입력 처리 구조를 개선하기 위한 작업을 진행했다. 또한 main 브랜치의 변경 이력을 바탕으로 릴리즈 노트를 정리했다.

## 1. 패키징 및 초기화 오류 분석

- **색상 프로퍼티 초기화:** `FCPTagDefinitionRow`의 `FLinearColor` 멤버 3개에 명시적 초기값이 없음을 확인했다. UI와 포션 효과에서 색상 및 알파값을 사용하는 점을 고려하여 `FLinearColor::White`로 초기화된 것을 확인했다.
- **MCP 포트 충돌:** Windows 쿠킹 과정에서 기존 에디터가 사용 중인 8000번 포트에 MCP 서버가 중복으로 실행되면서 실패한 것을 확인했다. `StopServer`는 HTTP 리스너까지 종료하지 않으므로, MCP 자동 시작 설정을 비활성화한 뒤 에디터를 재실행하는 대응 방법을 정리했다.

색상 초기화는 소스에 반영됐지만, 수정 후 빌드와 재쿠킹 결과는 아직 확인하지 않았다.

## 2. 인벤토리 아이템 반환 및 획득 정책 개선

인벤토리의 공간 부족 상황에서 아이템이 어떻게 처리되어야 하는지 정리했다.

- 창을 닫을 때 손에 든 아이템을 가능한 만큼 반환하고, 남은 수량은 월드에 드롭한다. 해당 드롭 호출이 소스에 반영된 것을 확인했다.
- 맵 이동 시에는 수납 가능한 수량만 보존하고 잔량은 다음 맵으로 넘기지 않는다.
- 아이템 배치 시 자동 회전을 제거한다. 자동 회전 재탐색 제거가 반영된 것을 확인했다.
- 채집 시 수납하지 못한 아이템은 월드에 드롭하고, 월드 아이템을 집을 때는 사전에 수납 공간을 검사하는 방향으로 변경안을 정리했다.

UE 5.8 엔진 소스를 확인한 결과, 월드 종료 중에는 `SpawnActor`가 제한된다. 따라서 일반적인 창 닫기와 `EndPlay`에서의 반환을 동일하게 처리할 수 없다. 또한 반환 과정에서 순회 중인 배열을 비우는 코드가 발견되어 루프 종료 후 초기화하도록 수정할 필요가 있다.

반환 및 획득 정책의 전체 동작은 아직 플레이 테스트를 통해 검증하지 않았다.

## 3. 인벤토리 클릭 지연 및 입력 누락 분석

기존 인벤토리 입력은 단일 클릭과 더블클릭을 구분하기 위해 `DoubleClickTime`(0.2초)만큼 대기한 후 집기·놓기·드롭을 실행했다. 별도의 게임플레이 더블클릭 동작은 확인되지 않았으며, 현재는 이 대기 타이머가 제거되어 좌클릭을 즉시 처리하도록 변경됐다.

그러나 타이머 제거 이후에도 빠른 두 번째 클릭이 누락되는 문제가 있었다. Slate Debugger의 입력 로그를 통해 `MouseButtonDown`은 정상 처리되지만 `MouseButtonDoubleClick`은 슬롯에서 처리되지 않는 것을 확인했다.

| 재현 상황 | 관측 결과 |
| --- | --- |
| 동일 슬롯 집기 후 놓기 | 두 번째 클릭이 더블클릭 이벤트로 전달되어 놓기 미실행 |
| 바깥 연속 드롭 | 9회 중 일반 클릭 5회 처리, 더블클릭 4회 미처리 |

Slate에서는 일반 클릭과 더블클릭을 서로 다른 이벤트로 전달한다. 따라서 대기 타이머를 제거하는 것만으로는 연속 클릭을 모두 처리할 수 없다. 공통 슬롯 클래스의 `NativeOnMouseButtonDoubleClick`에서 왼쪽 버튼 입력을 기존 `NativeOnMouseButtonDown`으로 전달하는 변경안을 정리했다.

변경안 적용 후 재시험은 아직 진행하지 않았다. 인벤토리 UI 전체 재생성 및 리소스 동기 로드에 따른 성능 비용도 별도 측정이 필요하다.

## 4. 릴리즈 노트 정리

main 브랜치의 커밋 이력과 최종 변경 사항을 확인하고 저장 슬롯·자동 저장, 가마솥 제작 UI, 채집 콘텐츠, 투척 가이드 및 포션 효과 개선 등을 릴리즈 노트로 정리했다.

## 정리

이번 작업을 통해 입력 처리 지연과 입력 이벤트 누락을 구분하여 분석할 수 있었다. 특히 엔진의 이벤트 전달 방식과 프로젝트의 입력 처리 구조를 함께 확인하고, 실제 로그로 문제를 검증하는 것이 중요하다는 점을 확인했다. 아이템 반환 역시 월드 생명주기에 따라 처리 방식을 구분해야 한다.
