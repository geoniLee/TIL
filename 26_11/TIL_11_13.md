# TIL - 2026.11.13

## 오늘 진행한 내용

CreatePotion의 인벤토리 및 컨테이너 시스템에서 데이터 관리와 UI의 책임이 적절하게 분리되어 있는지 검토했다. 또한 월드에 생성된 아이템이 공중에 정지하는 문제를 조사하고, 채집 및 아이템 획득 시 수납 공간을 처리하는 방식을 정리했다.

## 1. Inventory / Container 책임 분리

기존 구조에서는 컨테이너가 아이템의 배치와 수량을 관리하지만, 외부 객체에서도 내부 배열을 직접 수정하거나 수납 가능 여부를 별도로 계산하고 있었다. 이러한 구조는 같은 규칙이 여러 곳에 구현되어 기능 변경 시 일관성을 유지하기 어렵다.

이를 개선하기 위해 다음과 같이 책임을 구분했다.

- **Container:** 수납 가능 여부 판단, 아이템 배치·수량 변경 및 변경 알림을 담당한다. 외부에서는 데이터를 읽거나 변경을 요청하고, 파생 클래스도 공통 변경 기능을 우선 사용한다.
- **Inventory:** 플레이어 가방에 특화된 기능을 담당하며, 공통 수납 규칙은 Container를 활용한다.
- **UI:** 화면 표시와 숨김, UI 내부 입력 처리 및 사운드를 담당한다.
- **Controller:** 아이템 반환과 손 상태 정리를 요청하되, 구체적인 반환 처리는 직접 담당하지 않는 방향으로 정리했다.

확정된 범위에 대해 변경 코드를 작성하고 패치 적용 가능 여부를 정적으로 확인했다. 실제 저장소 반영과 빌드는 수행하지 않았으며, 아이템 반환 구현의 담당 위치와 컨테이너별 입력 동작의 추상화 방식은 추가 검토 대상으로 남겼다.

## 2. 월드 아이템의 물리 시뮬레이션

채집 잔량이나 인벤토리에서 버린 아이템이 공중에 정지하는 문제를 조사했다. 기존 Spawn 경로는 Actor 생성과 아이템 데이터 초기화만 수행하지만, 투척 경로는 물리 시뮬레이션 활성화와 초기 속도 설정까지 수행한다.

재료 Blueprint의 기본 설정을 확인한 결과, 중력은 활성화되어 있었지만 루트 Mesh의 물리 시뮬레이션은 비활성화되어 있었다. **중력 설정만으로는 물리 시뮬레이션이 시작되지 않는다.**

이에 따라 생성된 아이템의 `Resting` 상태는 유지하면서 루트 Mesh의 물리 시뮬레이션을 기본 활성화하도록 변경한 것을 확인했다. 부유 연출을 담당하는 자식 Mesh의 물리 설정은 기존대로 유지한다.

다만 투척·드롭 이후에는 감쇠와 정지 처리가 적용되는 반면, 일반 Spawn에는 동일한 처리가 없다. 생성된 아이템이 빠르게 움직이는 현상도 보고되었으나, 초기 속도나 충돌 상태를 직접 관측하지 않아 정확한 원인은 확정하지 못했다.

## 3. 채집 및 월드 아이템 획득 처리

채집 과정에서 가방에 넣지 못한 수량을 임시 인벤토리로 보내는 기존 방식 대신, 실제 미수납 수량만 월드에 생성하도록 변경했다. 월드 아이템을 집을 때도 기존 손 아이템을 교체하기 전에 수납 가능 여부를 검사하도록 변경된 코드를 확인했다.

이 과정에서 획득 API에 따라 잔량의 처리 방식이 다르고, 집기 기능에서 컨테이너의 수납 판단 로직을 중복 구현하고 있다는 문제를 발견했다. 따라서 개별 기능의 획득 정책과 공통 수납 규칙을 분리하고, 동일한 수납 판단을 재사용하도록 책임 분리 변경안을 작성했다.

기능 변경의 소스 반영은 확인했지만 실제 플레이 결과와 Actor 생성 실패 시의 잔량 처리 정책은 아직 검증하지 않았다.

## 정리

오늘은 기능을 구현하는 것뿐 아니라 각 객체가 어떤 책임을 가져야 하는지 검토했다. 특히 **데이터의 변경 권한과 공통 규칙을 해당 데이터를 관리하는 객체에 집중시키는 것이 중복 구현과 상태 불일치를 줄이는 데 중요하다**는 점을 정리했다.

또한 Actor 생성과 데이터 초기화, 물리 활성화는 서로 다른 처리이며, 생성 경로에 따라 물리 상태와 후속 동작이 달라질 수 있음을 확인했다.
