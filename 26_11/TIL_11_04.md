# TIL - 2026.11.04

## 오늘 진행한 내용

Save/Load 슬롯 UI의 연결 상태와 위젯별 책임을 점검하고, 다른 팀원의 환경에서 일부 저장 데이터가 복원되지 않는 현상의 원인을 조사했다. **UI 그래프에서 확인한 연결 상태**와 **실제 저장·불러오기 실행 검증**을 구분하여 기록했다.

## 1. Save/Load 슬롯 UI 연결 및 함수 분리 검증

### 위젯별 역할 정리

저장 처리를 하나의 위젯에 집중시키지 않고 역할을 다음과 같이 구분했다.

- **PauseMenu:** 저장 모드의 슬롯 선택 창 열기
- **CPSaveSubsystem:** 실제 저장·불러오기 처리
- **SaveLoad WBP:** 슬롯 표시 문구 갱신, 저장 결과 알림 및 사용자 입력 처리

`Common SaveLoad`에서는 `UpdateSlot`과 `ProcessSaveResult`를 분리하고, 세 저장 경로에서 반환값이 전달되는 구조를 확인했다. `Book SaveLoad`에서는 `ShowOverwriteConfirm`과 `HandleOverwriteConfirmed`로 덮어쓰기 처리를 나누고, 확인창의 `OnConfirmed`를 `Create Event`로 함수에 바인딩하는 변경안을 정리했다.

또한 Settings의 Soft Class 참조를 `Get Class Defaults`로 가져와 Blocking 로드한 뒤 같은 참조를 Resolve하여 `PushWidget`에 전달하는 기존 방식이 유효한지 확인했다.

### 블루프린트 그래프 확인 결과

- PauseMenu에서 저장 슬롯 창을 여는 연결 확인
- Common / Book SaveLoad에서 슬롯별 Save·Load 및 반환 결과 처리 연결 확인
- Title Continue 버튼이 **Slot1 또는 Slot2에 저장 데이터가 있으면** 활성화되고 Section 2로 이동하는 조건 확인
- `BP_CPBookData`의 Section 2 오른쪽 페이지 등록과 Book SaveLoad의 Section 0 Back 연결 확인
- Book 위젯의 불필요한 Dispatcher 제거 확인
- 덮어쓰기 확인창의 `SlotIndex <= 2` 조건이 의도한 설정임을 확인

### 남은 검증 사항

- `Create Event`에 실제 선택된 함수명은 도구상 확인하지 못함
- Common 위젯과 Title에 남은 불필요한 노드 정리 필요
- 팝업 ZOrder가 `PauseMenu=100`, `SaveLoad=0`, `Confirm=0`으로 확인되어 표시 순서 조정 필요
- 저장 알림의 `ShowNotification`은 ZOrder 인자 없이 `AddToViewport`를 호출하므로 **WBP 기본 ZOrder 값 변경만으로 알림 표시 순서를 보장할 수 없음**
- **실제 저장·불러오기 실행 테스트는 수행하지 않음**

## 2. 저장 데이터 일부 복원 누락 원인 조사

다른 팀원 환경에서 **레벨은 복원되지만 인벤토리·도감·플레이어 위치는 복원되지 않는 현상**이 보고되어 저장과 로드 경로를 비교했다. 다른 데이터의 복원 여부는 확인되지 않았다.

### 저장·복원 흐름 확인

현재 SaveGame은 월드 시간, 인벤토리, 채집물, 도감, NPC, 퀘스트, 가마솥, 레벨, 플레이어 위치·회전을 수집한다. 최근 슬롯 관련 변경은 주로 슬롯 인자, 파일명, 반환값에 집중되어 있었으며 인벤토리·도감의 수집·복원 함수와 저장 데이터 구조는 변경되지 않았음을 확인했다.

복원 시점은 데이터마다 달랐다.

- **인벤토리:** `InventoryComponent.BeginPlay`에서 대기 데이터를 한 번 소비
- **플레이어 위치:** `PlayerController.SetPawn`에서 한 번 적용
- **도감:** `SaveSubsystem.LoadGame`에서 즉시 적용

따라서 한 가지 아이템 에셋 참조 문제나 인벤토리의 일회성 데이터 소비만으로 세 증상을 동시에 설명하기는 어렵다.

### 원인 후보 및 확인되지 않은 부분

게임 상태 적용을 생략한 로드 경로 또는 로드 이후 `ResetGameSession` 호출은 **레벨만 복원되는 현상을 설명할 수 있는 가설**이다. 다만 현재 Book SaveLoad는 `SaveSubsystem.LoadGame`을 거치며, 확인된 `ResetGameSession` 호출 위치는 Title BookMenu의 Construct이다. **로드 이후 다시 호출됐다는 증거는 확보하지 못했다.**

또한 레벨명과 플레이어 위치는 저장 시 동일한 Pawn 유효 분기에서 수집되며, `SaveGame`의 `bool` 반환값은 **파일 저장 성공 여부**를 나타낼 뿐 각 데이터가 올바르게 저장되었는지까지 보증하지 않는다.

문제가 발생한 환경에서 재현하거나 저장 파일 내부 데이터를 확인하지 못했으므로 **원인은 미확정이며 수정도 적용하지 않았다.**

## 정리

Save/Load UI는 화면 호출, 데이터 처리, 결과 표시의 책임을 나누어 관리하는 구조임을 확인했다. 반면 블루프린트 그래프에서 연결이 정상인 것과 실제 플레이에서 저장·복원이 정상 동작하는 것은 별도로 검증해야 한다.

저장 데이터 복원 문제도 파일 생성 성공만으로 데이터 정합성을 판단할 수 없다는 점을 확인했다. 다음 단계에서는 문제 환경에서 저장 파일의 실제 내용과 로드 경로, 데이터 적용 시점을 확인해 원인을 좁혀야 한다.
