# TIL - 2026.11.02

## 오늘 진행한 내용

Save/Load 슬롯 UI의 공통화 가능성을 검토하면서 Unreal Widget의 상속 구조와 생명주기를 확인했다. 또한 Unreal Editor 실행 시 발생하는 `GameFeatureData` 관련 Asset Manager 경고의 원인을 플러그인 의존성과 프로젝트 설정을 기준으로 조사했다.

## 1. Save/Load 슬롯 위젯 상속 구조 분석

### 기존 구조 확인

Save/Load 슬롯 UI를 인게임 팝업과 타이틀 Book Menu에서 공통으로 사용할 수 있는지 검토했다.

- `WBP_CP_Common_Option`: `UCPBasePopupWidget`을 부모로 사용
- `WBP_CP_Title_BookMenu_Option`: BookMenu 플러그인의 `UBookPageWidget`을 부모로 사용

두 위젯은 외형이나 Save/Load 기능은 유사하지만, 필요한 부모 기능과 동작 주기가 다르다.

- **Popup 계층:** UI Manager와의 연동, ESC 입력에 의한 닫기 처리
- **BookPage 계층:** `BookMenuActor`, 페이지 인덱스 및 `Init` 생명주기 관리

따라서 두 위젯을 단순히 공통 부모인 `UCPBaseUserWidget` 하나로 통합하면 각 계층에 필요한 동작을 그대로 유지하기 어렵다는 점을 확인했다.

### 정리한 설계 방향

**Save/Load의 데이터 처리 및 슬롯 관련 로직은 공유하되, 표시 위젯은 Popup과 BookPage의 상속 계층을 각각 유지**하는 방향이 적절하다고 판단했다.

현재 `CPUISettings.h`에는 Popup·BookPage·Confirm 위젯 설정용 필드가 `TSoftClassPtr<UUserWidget>` 타입으로 추가되어 있으나, `DefaultGame.ini`에는 해당 설정값이 없으며 대응하는 SaveLoad/Confirm WBP 자산도 아직 준비되지 않은 상태다.

후속 작업으로는 실제 위젯 부모 타입에 맞게 설정 필드의 타입을 제한하고, 필요한 WBP 자산을 생성·지정하는 과정이 남아 있다. 또한 Public 설정 헤더에 `UBookPageWidget` 타입을 직접 노출한다면 `CreatePotion.Build.cs`의 `BookMenu` 모듈 의존성을 Public으로 조정해야 한다는 점도 확인했다.

## 2. GameFeatureData Asset Manager 경고 원인 조사

### 발생 구조

Unreal Editor 시작 시 발생한 `GameFeatureData` 관련 Asset Manager 경고를 조사했다.

프로젝트에서 `AllToolsets`를 활성화하면 다음 경로를 통해 `GameFeatures` 플러그인까지 활성화된다.

```text
AllToolsets
  └─ GameFeaturesToolset
       └─ GameFeatures
```

그러나 현재 `DefaultGame.ini`의 `UAssetManagerSettings` 설정에는 `GameFeatureData`를 검색하기 위한 `PrimaryAssetTypesToScan` 규칙이 존재하지 않는다. 이처럼 **Game Features 플러그인은 활성화되어 있지만 필요한 Asset Manager 스캔 규칙이 없는 상태**가 해당 경고의 직접 원인임을 확인했다.

### 대응 방향

프로젝트에서 Game Feature Plugin을 실제로 사용하는지에 따라 대응 방법을 구분할 수 있다.

- **사용하는 경우:** `GameFeatureData`에 필요한 `PrimaryAssetTypesToScan` 규칙을 프로젝트 설정에 추가
- **사용하지 않는 경우:** `AllToolsets` 전체 활성화 대신 필요한 Toolset만 선택적으로 활성화하는 방안 검토

이번 조사에서는 경고의 발생 경로와 설정 누락을 확인했다. 설정 변경에 따른 경고 해소 여부까지 검증한 것으로 기록하지 않는다.
