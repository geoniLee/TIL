# TIL - 2026.11.03

## 오늘 진행한 내용

Save/Load UI 연결 작업을 검토하고, Q/E 아이템 순회 기능을 포션 이외의 인벤토리 아이템까지 확장하기 위한 기존 코드 구조를 분석했다. 특히 기존 기능의 구현 상태와 변경이 필요한 지점을 구분하고, 실제 적용 전 검증할 사항을 정리했다.

## 1. Save/Load UI 연결 작업

Save/Load 기능을 인게임 옵션 화면과 타이틀의 Book Menu에 연결하는 작업을 대상으로 기존 위젯의 상속 관계와 설정 구조를 확인했다.

- 인게임 옵션의 `WBP_CP_Common_Option`은 `UCPBasePopupWidget` 계층을 사용하며, UI Manager 및 ESC 종료 동작과 연결된다.
- 타이틀의 `WBP_CP_Title_BookMenu_Option`은 `UBookPageWidget` 계층을 사용하며, `BookMenuActor`, 페이지 인덱스 및 `Init` 생명주기에 의존한다.
- 두 화면을 하나의 공통 부모 위젯으로 단순 통합하면 기존 동작을 유지하기 어려우므로, **Save/Load의 슬롯 처리 로직은 공유하고 화면 위젯은 각각의 계층을 유지**하는 방향이 적절하다.

기존 조사에서는 `CPUISettings.h`에 Popup·BookPage·Confirm 위젯용 설정 필드가 추가된 상태였으나, `DefaultGame.ini`의 설정값과 이에 대응하는 SaveLoad/Confirm WBP 자산은 아직 확인되지 않았다. 따라서 **UI 연결 완료나 전체 시나리오 테스트 성공으로 간주하지 않는다.**

## 2. Q/E 아이템 순회 구조 분석 및 변경안 작성

현재 Q/E 아이템 순회가 포션 중심으로 동작하는 원인을 살펴봤다.

- `CPItemWheelWidget::RefreshPotionList()`의 `IsPotion()` 필터가 순회 목록을 포션으로 제한하고 있었다.
- `CarryComponent`는 이미 `ACPThrowablePropBase`를 받을 수 있어, 일반 Throwable 아이템을 드는 기능 자체를 확장할 필요는 없었다.
- 반면 `CPPlayerController::EquipItemAtGridIndex()`는 `SpawnActor<ACPPotionActor>()`를 사용하여 **장착 대상 생성 단계에서 포션 타입을 전제**하고 있었다.

이를 바탕으로 다음 변경 방향을 정리했다.

1. 아이템 휠에서 포션 전용 필터를 제거하여 대상 인벤토리 아이템을 순회 목록에 포함한다.
2. 선택 아이템을 `ACPThrowablePropBase` 기준으로 생성·초기화·장착하도록 변경한다.
3. 일반 아이템에는 포션 전용 액체 레이어가 표시되지 않도록 분기한다.
4. 기존 포션의 가상 초기화 동작은 유지한다.

현재 인벤토리의 대상 범위는 Throwable Actor 기반 아이템이며, 씨앗은 폐기된 콘텐츠로 확인했다. **관련 두 파일의 변경 전·후 코드안을 작성했지만, 저장소에 직접 적용하거나 빌드를 수행하지는 않았다.**

## 정리

Save/Load UI는 **공통 로직과 화면별 위젯 생명주기를 분리**하는 것이 중요하며, 설정과 WBP 자산 연결을 별도로 검증해야 한다는 점을 정리했다.

Q/E 아이템 순회는 입력 처리나 CarryComponent 자체보다 **순회 필터와 장착 시 Actor 생성 타입**이 확장을 제한하는 핵심 지점임을 확인했다. 이후 변경안을 실제 적용할 경우 포션과 일반 Throwable 아이템 모두에서 순회·장착·표시가 정상적으로 동작하는지 검증할 필요가 있다.
