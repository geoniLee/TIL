# TIL - 2026.11.11

## 오늘 진행한 내용

Inventory / Container 관련 코드 구조를 조사하고, 아이템 구매·이동·반환 과정에서 발생할 수 있는 문제와 개선 방향을 정리했다. 공통 Container, Inventory, Hand, Lab, Shop, Drop 및 저장 Subsystem과 UI 연결 경로를 확인했다.

## 1. Inventory / Container 구조 및 구매 처리 확인

상점 구매 시 구매 수량을 전부 수납할 수 없다면 구매를 차단하는 방향으로 정리했다.

- 현재 소스에는 **임시 컨테이너로 전량 수납 가능 여부를 먼저 확인**한 뒤 결제·상점 재고 차감·구매 결과 반영을 수행하는 구조가 적용되어 있다.
- 제외하기로 한 재고 수량 재검증 로직은 아직 남아 있어 추후 정리가 필요하다.
- 현재 사용하지 않는 Seed 아이템 관련 `bIsSeed` 분기 및 이를 위한 Prop 초기화 API 확장은 개선 범위에서 제외했다.
- 실제 호출 경로를 확인하지 못한 원본 변경 콜백이나 팝업 중 재고 변경은 확정된 문제로 취급하지 않았다.

## 2. 손에 든 아이템의 반환 및 잔량 처리

`ReturnHeldItemToOrigin`은 원래 컨테이너로 반환하고 남은 수량이 생겼을 때 현재 **로그만 남기고 `ResetHoldingItem`을 호출**하는 구조로 확인됐다. 수납되지 않은 잔량을 바닥에 드롭하도록 하는 변경안을 검토했다.

- 반환에 성공한 수량만 차감하고, 남은 수량은 기존 Prop 초기화 API를 사용해 드롭하는 방향으로 정리했다.
- `EndPlay`에서도 수납 가능한 수량만 되돌리고 잔량은 다음 맵에 보존하지 않는 방향을 설정했다.
- 다만 UE 5.8의 월드 종료 처리에서는 `bIsTearingDown` 검사로 `SpawnActor`가 거부될 수 있으므로, **`EndPlay` 시점에 실제 잔량 드롭을 보장할 수 없다.** 종료 전에 드롭을 반드시 실행해야 한다면 맵 이동 전 단계로 처리 시점을 옮겨야 한다.

이를 통해 일반적인 아이템 반환과 월드 종료 중 정리 작업은 **실행 가능한 시점이 다르다는 점**을 확인했다.

## 3. 가마솥으로의 포션 자동 이동 경로 분석

공통 `Ctrl` 이동에서 포션이 가마솥으로 들어갈 수 있는 경로를 조사했다.

- 인벤토리 단독 사용 시에는 이동 대상이 없고, 상점에서는 판매 팝업 경로로 분기한다.
- 가마솥의 `bUseSlotUI` 경로에서는 Lab 컨테이너가 열려 공통 자동 이동 기능을 이용할 수 있다.
- Unreal MCP를 통해 `BP_CP_Cauldron`의 `bUseSlotUI=true`, `LabContainerComponent`의 `TargetContext=Lab`, `MaxSlots=2`, `ContainerUIClass=WBP_CP_Cauldron_Main` 설정을 확인했다.
- 현재 C++ 자동 이동 경로에는 **포션의 Lab 컨테이너 진입을 차단하는 검사가 없다.** 따라서 포션 차단 조건이 필요한 구조로 판단했다.

자동 이동 시 포션 효과 보존을 추가하는 방안은 잘못된 이동을 허용하는 것을 전제로 하므로 필수 개선 대상에서 제외했다. 다만 해당 경로를 **실제 플레이에서 재현한 것은 아니다.**

## 4. 추가 코드 안정성 검토

- `TryPlaceHoldingItem`: 유효성 검사 이전에 참조를 사용하는 경로를 확인해 역참조 순서 개선이 필요하다.
- `TryBindInput`: 캐스트 실패 시 재시도 처리와 관련한 문제를 검토했다.

이 항목들은 코드 분석에서 확인한 개선 대상으로, 수정이나 실행 검증까지 진행한 것은 아니다.

## 정리

오늘은 아이템을 **구매·자동 이동·반환·맵 전환**하는 과정에서 각 시스템의 책임과 예외 상황을 확인했다. 구매 시 수납 가능 여부를 먼저 검사하는 기존 구현은 확인했으며, 반환 잔량 처리와 포션의 가마솥 이동 차단은 후속 개선 항목으로 남았다.

특히 `EndPlay`에서는 월드가 이미 종료 중일 수 있어 Actor 생성에 의존하는 정리 로직을 보장하기 어렵다는 점, UI에서 보이는 동작뿐 아니라 공통 입력 처리와 컨테이너 설정까지 추적해야 실제 허용 경로를 파악할 수 있다는 점을 확인했다.
