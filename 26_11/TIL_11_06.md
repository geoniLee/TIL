# TIL - 2026.11.06

## 오늘 진행한 내용

Unreal Engine 5.8 기반 프로젝트의 **Save/Load UI 동작과 데이터 복원 오류**를 분석했다. 저장 슬롯 파일과 실행 로그를 비교하고 진단 로그를 추가해 복원 누락이 발생하는 시점을 추적했다. 별도로 **기업 인·적성검사의 유형과 준비 방식**을 조사했다.

## 1. Save/Load UI 및 입력 모드 분석

### Confirm 종료 후 입력 모드 전환

- Common·Book SaveLoad, Confirm, PauseMenu, Title BookMenu의 블루프린트 그래프와 UIManager 코드를 확인했다.
- Book SaveLoad에서 Confirm을 닫으면 `OpenWidgets`에 남는 UI 요청이 없어 `GameOnly`로 전환되는 경로를 로그에서 확인했다. 인게임 SaveLoad에서는 남은 UI에 따라 `UIOnly`가 유지되는 사례와 차이가 있었다.
- BookMenu는 일반 Popup과 다르게 관리되므로, **Book 페이지의 생명주기와 UIManager의 입력 모드 관리**를 연결할 필요가 있음을 정리했다.
- 첫 페이지에서 `RegisterCreatedWidget(Self)`를 연결한 상태를 그래프에서 확인했다. Continue 버튼은 슬롯이 없을 때 비활성화하는 대신 `Collapsed`로 숨기는 변경안을 검토했다.
- Common SaveLoad의 확인창 문구 선택 결과가 `MessageText.SetText` 입력으로 이어지지 않는 연결 누락도 확인했다.

### 로딩 화면 처리

- 새로 시작 경로와 SaveLoad의 로드 경로를 비교했다. 저장 데이터를 불러온 뒤에는 복원된 시간대와 `LevelName`을 기준으로 로딩 화면을 선택하는 변경안을 작성했다.
- 기존 `SetLoadingScreen`과 배경 인덱스 매핑을 재사용하는 방향이며, **해당 변경안의 직접 적용·실행 검증은 수행하지 않았다.**

## 2. 저장 파일 검증 및 복원 오류 추적

### Slot1·Slot2 파일 분석

- `Slot1.sav`: 약 80KB. 게임 시간 **426분**, 인벤토리 **8항목**, 채집 노드 **195개**, 채집 도감 **6개**, 태그 **7개** 등 진행 데이터가 포함돼 있었다.
- `Slot2.sav`: **2,523바이트**. 시간 **2분** 및 레벨·위치 등의 기본 정보는 있으나 인벤토리·도감 진행 데이터는 확인되지 않았다.
- 두 파일의 GVAS 속성 경계에서 잘림이나 길이 불일치는 발견하지 못했다. 다만 **속성의 직렬화 생략이 곧 파일 손상을 의미하지는 않으며**, 파일 내용만으로 데이터가 처음부터 비어 있었는지, 저장 과정에서 빠졌는지는 판단할 수 없다.

### 진단 로그 추가 및 재현

`CPSaveSubsystem.cpp`와 `CPContainerSubsystem.cpp`에 **`[SaveLoad]` 진단 로그 60개**를 적용했다. 슬롯 파일 읽기·쓰기, 데이터 전달, 복원 대기, 인벤토리·위치 적용, 세션 초기화 호출을 구분해 출력하도록 구성했다. 기존 복원 순서나 반환 조건은 변경하지 않았으며 UE 5.8.1 Development 빌드에서 컴파일과 링크가 성공했다.

문제 재현 로그에서는 다음 순서를 확인했다.

1. `Slot1`의 인벤토리 8개와 도감 데이터가 정상적으로 읽히고, 복원 대기 상태가 설정됐다.
2. Confirm 종료와 BookMenu 포커스 처리 직후 **`ResetGameSession`이 재호출**됐다.
3. 이후 Pawn 위치 및 인벤토리 복원 시점에는 대기 상태가 해제되어 적용이 생략됐다.
4. 그 상태에서 `Slot2`에 저장하면서 초기화된 데이터가 기록됐다.

따라서 **이번 재현에서 직접 확인된 복원 누락 원인은 로드 직후의 세션 초기화**였다. 저장 파일의 읽기 실패가 원인은 아니었다.

### 위젯 생명주기와 후속 검증

- `WBP_CP_Title_BookMenu`의 `Construct`에 `ResetGameSession`이 연결돼 있음을 확인했다.
- `UIManager`의 포커스 복원 과정에서 호출되는 `TakeWidget()`이 위젯 재구성을 유발할 수 있다는 엔진 소스 구조를 확인했다. **Confirm 종료 → 포커스 복원 → BookMenu Construct 재실행**은 유력한 호출 경로지만, 해당 순간의 전체 호출 스택은 확보하지 못했다.
- 후속 재시험에서는 Confirm 종료 후 포커스 대상이 **BookMenu_SaveLoad**로 기록됐고, 세션 초기화 재호출 없이 **위치와 인벤토리 8항목이 정상 복원**됐다. 이어진 Slot2 저장에도 진행 데이터가 반영됐다.
- 이 시험 경로에서는 문제가 개선됐으나 **다른 페이지 이동 경로와 Slot2 재로드까지 검증한 것은 아니다.** 위젯 수명주기에서 반복 실행될 수 있는 `Construct`에 게임 상태 초기화를 배치하는 설계는 별도로 정리할 필요가 있다.

## 3. R&D — 기업 인·적성검사

### 검사 목적과 구분

기업의 인·적성검사는 채용 전형에서 지원자의 **기초 인지·문제해결 역량**과 **직무·조직에 대한 성향 적합성** 등을 평가하는 데 활용된다. 구체적인 평가 영역과 적용 여부는 회사·채용 직무에 따라 다르다.

| 구분 | 일반적인 평가 내용 | 준비 관점 |
|---|---|---|
| 적성·인지 검사 | 언어 이해, 수리·자료 해석, 논리·추론, 문제해결 등 | 출제 유형 파악, 시간 제한 풀이, 오답 원인 분석 |
| 인성·성향 검사 | 업무 태도, 가치관, 협업 성향 등 | 질문을 정확히 읽고 실제 자신의 기준에 따라 일관되게 응답 |
| 직무별 별도 평가 | 코딩 테스트, 기술 지식, 실무 문제해결 과제 등 | 모집 공고에 명시된 직무별 평가 방식 확인 |

NCS가 제공하는 직업기초능력·채용모델 문항도 의사소통, 수리, 문제해결 등 역량을 학습하는 **참고 자료**가 될 수 있다. 단, NCS 문제 형식이 모든 민간기업 검사와 동일한 것은 아니다.

### 기업별 공식 안내 비교

- **삼성:** GSAT는 상황 대처와 문제해결 관련 종합 역량을 평가하며, 온라인으로 진행된다. 삼성 채용 안내에는 **S/W 직군 대상 별도 SW 역량테스트**도 설명돼 있어 지원 직무별 평가 구분이 필요하다.
- **SK하이닉스:** SKCT는 **인지 영역(언어·수리·추리)**과 **심층 영역(가치관·성향·태도)**으로 구분된다. 공식 안내에 따르면 SW 직군에서는 인지 영역을 코딩 테스트로 대체한다.
- **LG CNS:** 신입 전형에서 **LG Way Fit Test(인성·적성)**와 **CNS Fit Test(기술 트렌드 및 AI 활용 문제해결)**를 구분한다. 공식 안내도 적성검사에서 어려운 문제를 표시하고 넘어가는 시간 관리와, 인성검사에서 자신의 생각에 따른 일관된 응답을 권한다.
