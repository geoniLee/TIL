# TIL - 2026.10.30

## 오늘 진행한 내용

Unreal Engine 5.8 개발 환경에서 **MCP 연결 자동화 및 작업 기록 규칙**, **Save/Load 2슬롯 작업 검증**, **Standalone 게임의 GPU 부하 측정**을 진행했다. MCP 운영 방식과 실제 저장·불러오기 동작을 점검하고, 레벨별 GPU 부하 차이를 수치로 확인했다.

## 1. Unreal MCP 자동화 및 작업 기록 규칙 검토

### MCP 구성 및 연결 상태 확인

- UE 5.8의 HTTP MCP 서버 자동 시작 설정 위치와 동작을 확인했다.
- `ModelContextProtocol`은 MCP 서버 본체이며, `AllToolsets`은 여러 개별 Toolset을 묶어 활성화하는 선택적 플러그인임을 확인했다.
- 따라서 MCP 서버 실행에 `ModelContextProtocol`은 필요하지만 `AllToolsets`은 필수가 아니다. `AllToolsets`을 사용하지 않는다면 필요한 `EditorToolset`, `UMGToolSet` 등을 별도로 활성화해야 한다.

## 2. Save/Load 2슬롯 작업 검증

### 슬롯 구조 및 저장 처리

- QuickSave 확장용 슬롯 `0`과 사용자 선택 슬롯 `1`, `2`를 구분했으며, 실제 파일명은 각각 `Slot0`, `Slot1`, `Slot2`로 매핑된다.
- 저장 시스템에서 고정 `SlotName` 사용을 제거하고, **슬롯 번호를 인자로 전달**하며 **저장 결과를 반환**하도록 변경된 내용을 확인했다.
- Save와 Load는 하나의 슬롯 선택 UI가 모드에 따라 동작하는 구조다.
- 빈 Load 슬롯을 선택할 수는 있지만 **"저장 데이터 없음"**을 표시하고 실제 로드는 진행하지 않는다. 현재 UI에는 파일명만 표시된다.
- 슬롯 존재 여부 확인은 `UCPSaveSubsystem`의 책임으로 두지 않는 구조임을 확인했다.

### 블루프린트 동작 확인

- Title 및 BookMenu 블루프린트의 `OpenLevel`/`LevelName` 참조와 BookMenu의 직접 `LoadGameFromSlot` 및 서브시스템 `LoadGame` 참조를 점검했다.
- `WBP_CP_Title`은 Legacy 자산으로 검증 대상에서 제외했다.
- 실제 사용하는 `WBP_CP_Title_BookMenu`에서는 `LoadGame(1)`이 **유효한 객체를 반환했을 때만** 로딩 화면 표시 및 레벨 이동을 실행하고, 반환 객체의 `LevelName`을 사용함을 확인했다.
- `WBP_CP_Common_PauseMenu`에서는 `SaveGame(1)` 반환값이 `true`일 때만 저장 알림을 생성함을 확인했다.

## 3. Standalone 게임 GPU 부하 모니터링

### 초기 실행 환경 및 측정

UE 5.8 Standalone 게임 프로세스를 대상으로 GPU 부하를 측정했다.

- 실행 환경: RTX 3060, D3D12 SM6, 창 모드 1280×720, Scalability Quality 2
- 초기 설정: `bUseVSync=False`, `FrameRateLimit=0`, 월드 `max tick rate 0`으로 프레임 제한 없음. 동적 해상도 비활성화
- 측정 결과: 전체 GPU 사용률 **95~98%**, 게임 프로세스 3D 사용률 **77.0~83.6%**
- 온도 **67~70°C**, 전력 **125~140W**, 프로세스 전용 VRAM 약 **2.82GB**

### 60FPS 제한 후 레벨별 비교

콘솔에서 `t.MaxFPS 60`을 적용하고 로그의 `max tick rate 60`을 확인했다.

| 측정 항목 | NewFieldLevel | VillageLevel |
| --- | --- | --- |
| 게임 프로세스 3D 사용률 | 약 30~36% | 약 85~94% |
| 전체 GPU 사용률 | 약 39~56% | 약 95~98% |
| GPU 전력 | 약 76~96W | 약 142~148W |
| GPU 온도 | 약 57~60°C | 기록에 별도 수치 없음 |

NewFieldLevel에서는 프레임 제한 이후 GPU 사용률과 전력·온도가 낮아졌다. 반면 VillageLevel은 60FPS 제한 상태에서도 GPU 사용률이 다시 포화되어, **동일한 프레임 제한에서도 레벨에 따라 부하가 크게 다름**을 확인했다.

### 확인한 한계 및 후속 분석

- `t.MaxFPS 60`은 이번 실행 세션에만 적용되었으며 저장된 `FrameRateLimit`은 여전히 `0`이었다.
- 프로젝트의 `UCPGameUserSettings`에서 `SetFrameRateLimit` 후 `ApplySettings`를 호출하는 방식으로 제한값 적용 및 저장을 검토할 수 있다.
- VillageLevel의 구체적인 GPU 병목 패스는 현재 측정만으로 특정할 수 없다. **GPU Visualizer** 또는 **Unreal Insights GPU Trace**를 사용한 추가 분석이 필요하다.
