# TIL - 2026.10.28

## 오늘 진행한 내용

프로젝트 담당 영역별 개발 방향을 공유하고, Git LFS 사용량 문제에 대해 논의했다. 이를 계기로 **Git LFS의 사용량 집계 방식**을 조사했다. 별도로 기존 **Rider + Codex** 개발 환경에서 Unreal Editor와 Notion을 연동할 수 있는 **MCP(Model Context Protocol)** 구조도 검토했다.

## 1. 프로젝트 개발 방향 논의

담당 영역별로 다음 작업 방향을 정리했다.

- **슬라임 키우기:** 슬라임 알 획득 및 부화 방식 등 콘텐츠 구성
- **Tag/NPC:** 태그 추가 범위 설정, 퀘스트용 NPC 기능과 배치·동선 검토, 레벨 이동이 가능한 NPC 관리 방식 확인
- **필드:** 채집물 추가 등 필드 콘텐츠 작업

또한 협업 중 제기된 **Git LFS 사용량 문제**를 논의했다. 사용량 집계 원리와 점검 항목을 중심으로 정리했다.

## 2. R&D - Git LFS의 동작과 사용량 관리

### Git LFS란?

Git LFS(Large File Storage)는 대용량 파일의 실제 데이터를 일반 Git 객체와 분리해 저장하고, Git 저장소에는 해당 데이터를 가리키는 **포인터 파일**을 기록하는 방식이다. 포인터에는 파일의 식별자(SHA-256 기반 OID), 크기 등의 정보가 포함된다.

게임 개발에서는 텍스처, 모델, 사운드처럼 크기가 큰 바이너리 파일을 버전 관리할 때 활용할 수 있다.

### Storage와 Bandwidth의 차이

| 항목 | 집계 대상 | 주요 발생 상황 |
| --- | --- | --- |
| **Storage** | 저장소에 연결된 LFS 객체의 저장량 | LFS 파일 및 새로운 버전 업로드 |
| **Bandwidth** | LFS 객체 다운로드 전송량 | Clone, Pull, LFS 다운로드 등 |

LFS로 관리되는 파일이 수정되어 다시 업로드되면, GitHub는 새 버전의 **파일 전체 크기**를 스토리지 사용량에 반영한다. 따라서 대용량 바이너리 파일을 반복 수정하면 사용량이 빠르게 증가할 수 있다.

또한 협업자가 파일을 업로드하거나 다운로드해도 LFS 사용량은 **저장소 소유자 계정**에 집계된다. 다른 사람이 소유한 저장소에 기여하는 경우, 개인 계정의 사용량과 저장소 소유자의 사용량을 구분해 확인해야 한다.

### 사용량 제한과 삭제 시 주의사항

GitHub의 LFS는 계정 요금제와 예산 설정에 따라 무료 사용량 및 초과 사용 제한이 달라진다. 한도 초과 시 추가 과금 또는 사용 차단이 발생할 수 있으므로, 실제 상태는 저장소 소유자의 **Billing 및 Budgets 설정**을 확인해야 한다.

단순히 작업 트리에서 파일을 삭제하거나 Git 기록을 정리하는 것만으로는 GitHub에 저장된 LFS 객체가 자동 제거되지 않는다. 원격 객체 삭제는 별도 조치가 필요하며, 저장소 삭제·재생성은 이슈와 기타 저장소 정보가 소실될 수 있으므로 신중하게 검토해야 한다.

### 향후 점검할 사항

- `git lfs ls-files`로 LFS 추적 파일 목록 확인
- `.gitattributes`에서 불필요하게 넓게 지정된 LFS 추적 규칙 확인
- 저장소 소유자 계정의 LFS Storage/Bandwidth 사용량 및 예산 설정 확인

## 3. R&D - MCP를 활용한 개발 도구 연동

### MCP란?

MCP(Model Context Protocol)는 AI 클라이언트가 외부 프로그램이나 데이터 소스의 기능을 공통된 방식으로 사용할 수 있도록 하는 프로토콜이다. **MCP 클라이언트**는 AI 에이전트 측에서 요청을 보내고, **MCP 서버**는 연결된 프로그램의 도구(Tools)와 데이터(Resource 등)를 노출한다.

기존 Rider + Codex 환경에서는 주로 C++ 코드와 프로젝트 파일을 분석·수정한다. MCP를 연결하면 이 범위를 확장해 **Unreal Editor 내부 상태의 조회·조작** 또는 **Notion 문서 조회·기록** 같은 작업을 하나의 에이전트 워크플로에 포함할 수 있다. 다만 실제 수행 가능한 기능은 연결한 MCP 서버가 제공하는 도구에 따라 달라진다.

### Unreal MCP: 에디터 분석 및 조작

Unreal Engine 5.8은 에디터 안에서 실행할 수 있는 실험적 **Unreal MCP** 플러그인을 제공한다. 공식 문서 기준으로 액터 생성, 라이팅 설정, 머티리얼 작업, 에디터 위젯 검사, 자동화 테스트 등 에디터 기능을 도구로 노출할 수 있다.

- Unreal Editor에서 **Unreal MCP**와 **All Toolsets** 플러그인을 활성화한다.
- 에디터 설정에서 서버 자동 시작을 활성화하거나 콘솔에서 `ModelContextProtocol.StartServer 8000`을 실행한다.
- 기본 로컬 연결 주소는 `http://127.0.0.1:8000/mcp`이다.
- 에이전트가 실제로 액터·레벨 정보를 조회할 수 있는지 확인한 후, 수정 작업을 검증한다.

이 방식은 소스 코드 분석과 별개로 **현재 에디터에 배치된 오브젝트나 레벨 상태를 확인**하려는 목적에 적합하다. 단, Unreal MCP는 실험적 기능으로 API와 도구 구성에 변경 가능성이 있다.

### Notion MCP: 개발 작업 기록

Notion MCP는 AI 에이전트가 접근 권한이 있는 Notion 페이지를 검색·조회·수정할 수 있게 한다. 이번 검토에서는 **정해진 양식에 맞춰 개발 작업 내용을 문서화하는 흐름**을 목표로 설정했다.

1. 기존 Notion 작업 기록 양식과 대상 페이지를 조회한다.
2. 분석한 작업 내용과 결과를 양식에 맞춰 정리한다.
3. 사용자 확인 후 페이지 생성 또는 업데이트를 수행한다.

Notion 공식 MCP 서버 주소는 `https://mcp.notion.com/mcp`이며, OAuth 인증이 필요하다. 실제 페이지 조회·작성 성공 여부는 아직 검증하지 않았다.

### Rider 2026.2.2 + Codex 연동 시 고려사항

JetBrains AI Assistant에서 외부 MCP 서버를 등록하는 공식 경로는 `Settings > Tools > AI Assistant > Model Context Protocol (MCP)`이다. Codex 에이전트에도 등록된 서버를 전달하려면 `Settings > Tools > AI Assistant > Agents`에서 **Pass custom MCP servers** 설정을 확인해야 한다.

- **Unreal MCP:** 로컬 HTTP 서버를 연결 대상으로 등록하는 방식을 검토했다.
- **Notion MCP:** 공식 원격 서버를 사용할 수 있으나, JetBrains의 MCP OAuth 로그인 지원에는 제약이 보고되어 있다. 별도 Codex CLI에서 `codex mcp login notion`을 이용하는 공식 인증 경로 또는 STDIO 브리지 사용 여부를 추가 확인할 필요가 있다.
- **Rider 자체 MCP Server:** 외부 에이전트가 Rider의 코드 분석·파일 수정 기능을 활용할 때 사용하는 별도 기능으로, Unreal MCP·Notion MCP와 역할이 다르다.

연동 후에는 **Unreal의 액터/레벨 조회**, **Notion의 페이지 조회**를 먼저 테스트하고, 변경 작업은 권한과 실행 결과를 확인하는 순서로 검증할 계획이다. 현재는 연결 구조를 조사한 단계이며, 세 시스템의 연동이 완료된 것은 아니다.

## 정리

이번 회의에서는 담당 영역별 개발 방향을 확인하고, 협업 중 발생한 Git LFS 사용량 문제를 논의했다. 조사 결과, Git LFS는 현재 파일의 용량뿐 아니라 **누적된 파일 버전과 다운로드**가 사용량에 영향을 미치며, 협업 저장소에서는 **저장소 소유자에게 사용량이 집계**된다는 점을 확인했다.

또한 MCP를 이용하면 기존 Rider + Codex의 코드 작업에 **Unreal Editor 상태 조회·조작**과 **Notion 작업 기록**을 연결할 수 있다는 구조를 파악했다. 다만 연결 설정, OAuth 인증, 실제 도구 호출 결과는 후속 검증이 필요한 상태다.
